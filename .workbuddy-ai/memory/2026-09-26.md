# 2026-09-26

## Rebrand to Poorprice.com

User supplied a logo (white-on-black stacked lockup, "Poorprice.com" with a
shopping-cart "P" emblem) and asked to add it "everywhere in the website".

### Asset pipeline
The master is white artwork on a **solid black field**, which can't be dropped onto
the site's white chrome as-is — and removing the background alone is worse, because
the mark's "P" stem, cart and wordmark are all white and simply vanish on white.
So two tone variants ship, chosen by **surface**, not by appearance:

- `*-dark.webp` = dark artwork → for light surfaces (header, admin)
- `*.webp`      = light artwork → for dark surfaces (footer `#383a4d`)

Background removal is a luminance ramp (alpha 0 below L≈18, 255 above L≈58) plus
un-multiplying the black backdrop, which keeps the blue fully opaque and preserves
edge anti-aliasing. The "dark" variant remaps pixels above L≈150 to a navy scaled by
relative luminance, so the original shading survives.

Assets live in `public/brand/`, consumed through `components/Logo.tsx`
(`<LogoLockup>` for headers/sign-in, `<LogoMark>` for tight spots). Verified the
result visually on both white and dark preview sheets before wiring anything up —
worth doing, since the failure mode (invisible white-on-white) is not obvious from
code.

### Two performance problems caught late
1. **No `sizes` prop on `next/image`.** For a logo drawn at ~172 px wide, Next assumed
   full-viewport width and generated a **3840 px candidate — an upscale of a 1979 px
   source**. On this machine (`sharp` not installed, so the slow fallback optimizer)
   that took **5.26 s per image** vs 0.28 s at 256 px. Fixed by passing an explicit
   `sizes` derived from the rendered height, and by downscaling the sources.
2. **Oversized source PNGs.** Full-size exports were 272–312 KB each. Downscaled to
   900 px wide and converted to WebP: **~37 KB**, an 8× reduction. `public/brand/`
   went from ~2.5 MB to 588 KB. Kept one PNG (`poorprice-lockup-dark.png`) for the OG
   image, since social crawlers are happiest with PNG/JPG.

### Accent recolour
The site accent was Kijiji purple (`#373373` / `#3B1E6D`), which clashed with the blue
logo. Sampled the artwork's dominant blue (`#0074F8`) and updated both palettes:
`--kijiji-purple*` → `--brand-primary*` in `globals.css` (24 call sites, renamed via
`replace_all` so the token name matches what it holds) and `brand` in
`tailwind.config.ts`. Also swept the hardcoded `#373373` literals in the 404 page,
listing page, admin shell role badge and users avatar fallback.

### The stale-dev-server trap (cost the most time)
Symptom: production pages rendered correctly but **never hydrated** — every
`/_next/static/**` chunk returned 500 and `next start` logged
`Cannot find module .next/server/pages/_error.js`.

Root cause: **port 3000 was a stale `next dev` for this very project**, left over from
an earlier session. It continuously rewrote `.next` with dev artifacts (no `BUILD_ID`,
no `server/pages`, unhashed chunks, `static/development/`), clobbering every production
build. My earlier project note calling port 3000 "another process on this machine" was
**wrong** — corrected in `MEMORY.md`.

Diagnosis path worth remembering: when a page renders but doesn't hydrate, check
whether the static chunks actually exist on disk, and compare `/_next/static/chunks/`
names against the hashed names in the HTML. Unhashed names = dev layout.

Fixing it also exposed that killing only the `start-server.js` child is not enough —
the `npm run dev` / `next dev` parents respawn it. Kill the whole tree.

### Also learned
- `next build` left a half-written `.next` after an `EPERM` on `.next/trace`, and the
  *next* build then failed with `Cannot find module for page: /_document` — a corrupt
  `pages-manifest.json`. Recovery is a genuinely clean `.next`, not a retry.
- Windows deletes/renames are blocked by the sandbox's fail-closed shim while any
  process holds the directory. Renaming works the moment the holder exits.
- From Git Bash, `taskkill /F /PID n` gets its flags mangled; prefix with
  `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`.
